# Expo: оценка мобильного приложения

## Вывод

Для проекта целесообразно создать отдельное Expo-приложение в монорепозитории, но не переносить текущие React-компоненты напрямую. Next.js App Router, DOM, CSS backdrop-filter, cookie и Radix UI завязаны на браузер. Общими должны стать модели, схемы Zod, аналитические вычисления, i18n-ключи и дизайн-токены.

## Предлагаемая структура

```text
apps/
  web/                 # текущий Next.js 16 интерфейс
  mobile/              # Expo Router + React Native
packages/
  domain/              # операции, аналитика, валюты, схемы Zod
  i18n/                # словари и типы ключей
  design-tokens/       # цвет, радиусы, motion-профили
  api-contracts/       # будущие DTO и клиенты API
```

## Что можно переиспользовать

- `src/lib/analytics.ts` после удаления web-специфичных импортов;
- схемы операций, валют и персонализации;
- статические каталоги сервисов и банковских предложений;
- словари локализации;
- вычисления комиссий, статусов и масок реквизитов;
- сценарии PIN и кодового слова через общий интерфейс защищённого хранилища.

## Что требуется реализовать заново

- Radix UI заменить на React Native primitives или Tamagui;
- cookie заменить на SecureStore/AsyncStorage, секреты хранить только в SecureStore;
- Recharts заменить на Victory Native или Skia-графики;
- CSS glass/glow перенести на BlurView, LinearGradient и Reanimated;
- Next.js маршруты заменить на Expo Router;
- browser share/download заменить на системные Share и FileSystem API.

## Безопасность

Текущая web-версия является демонстрацией. В нативном приложении PIN нельзя хранить как простой cookie или только локальный SHA-256. Нужны SecureStore/Keychain, аппаратная биометрия, серверная сессия, ротация токенов и threat-model до подключения реальных финансовых данных.

## План миграции

1. Выделить `domain`, `i18n` и `design-tokens` без изменения web-приложения.
2. Создать Expo Router shell с темой, локализацией и безопасным хранилищем.
3. Реализовать read-only главную, карты, операции и аналитику.
4. Перенести платёжные формы только после появления API-контрактов и серверной авторизации.
5. Добавить E2E через Maestro и отдельный release pipeline EAS.

Оценка: прототип read-only — 2–3 недели; функциональный банковский клиент с API, безопасностью и release-процессом — отдельный продуктовый этап.
