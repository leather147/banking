# Lumen Bank — спецификация релиза аналитики, безопасности и адаптивности

Дата фиксации: 2026-08-06
Статус: исполнимый план реализации
Целевая платформа: Next.js 16 App Router, React 19, TypeScript, Bun, Tailwind CSS, Radix UI

## 1. Цель релиза

Подготовить Lumen Bank как цельное банковское web-приложение: без перезагрузок при переходах, с полноценными демонстрационными операциями, аналитикой по счетам, безопасностью, поиском, адаптивной компоновкой, расширенной правовой информацией и стабильной работой на мобильных браузерах.

Релиз должен устранить визуальные дефекты из приложенных мобильных скриншотов, не менять узнаваемый бренд и не выдавать демонстрационные действия за реальные банковские операции.

## 2. Обязательные инварианты

1. Все внутренние переходы выполняются через App Router и `next/link`/`router.push`, без полной перезагрузки.
2. Каждая завершённая или созданная операция имеет динамический slug и отдельный экран результата.
3. Демо-операции всегда явно маркируются как демонстрационные и не заявляют о реальном движении денег.
4. Все пользовательские настройки сохраняются локально через существующий cookie/settings-слой с версионированной схемой.
5. Фоновая сетка остаётся видимой при отключении цветного фона.
6. Уважать `prefers-reduced-motion`, клавиатурную навигацию и touch-ввод.
7. На узких экранах ни один блок не создаёт горизонтальный скролл страницы.
8. Нижняя навигация не закрывает последний интерактивный элемент страницы.
9. Вся строковая UI-копия проходит через i18n-слой; русский и английский являются полными эталонными локалями.
10. Динамические эффекты не должны блокировать ввод и переключение темы.

## 3. Набор дефектов по мобильным скриншотам

### 3.1. Нижняя навигация перекрывает контент

- Добавить единый вычисляемый `--mobile-dock-safe-area`.
- Высота учитывает сам dock, `env(safe-area-inset-bottom)` и внешний отступ.
- Основной scroll-контейнер получает нижний padding не меньше этой величины.
- Модальные окна и cookie-banner располагаются выше dock либо временно скрывают dock.
- Последняя кнопка, карточка или ссылка всегда полностью доступна для тапа.

### 3.2. Карточки и формы обрезаются по горизонтали

- Удалить фиксированные минимальные ширины у form-shell, account-card и service-grid.
- На ширинах до 767 px использовать `min-width: 0`, `width: 100%`, `max-width: 100%`.
- Все grid-колонки на мобильном переводить в `minmax(0, 1fr)`.
- Длинные суммы, названия и статусы получают управляемое уменьшение шрифта, перенос или ellipsis только там, где полное значение доступно рядом.
- Поля оплаты и карточки счёта не выходят за viewport даже при масштабе интерфейса больше 1.

### 3.3. Плитки настроек обрезают заголовки

- Сетка адаптивна: две квадратные плитки только при достаточной ширине.
- При недостатке места плитки переходят в одну колонку или используют более компактную типографику.
- Заголовок не должен уходить под chevron.
- Developer-плитка скрыта до разблокировки и отделена сепаратором.
- Лицензии удаляются из корневой сетки и становятся шестой карточкой раздела правовой информации.

### 3.4. Модальные окна не помещаются по высоте

- Dialog content ограничивается `max-height: calc(100dvh - safe areas - spacing)`.
- Внутреннее содержимое прокручивается, заголовок/закрытие и нижнее действие остаются доступными.
- На узких экранах dialog превращается в нижний sheet либо полноэкранный layer.
- Cookie-banner не перекрывает заголовок, форму и dock одновременно.

### 3.5. Экран карты визуально ломается

- Карта сохраняет банковское соотношение сторон.
- Баланс, маска номера, имя и статус размещаются в независимых областях без наложения.
- Горизонтальная карусель использует scroll snap и корректный touch-pan.
- Вторая карточка-предложение присутствует даже при одной реальной карте.

### 3.6. Длинные уведомления и юридические блоки

- Текст имеет комфортную строку, адаптивный размер и `overflow-wrap:anywhere` только для ID/URL.
- Экран уведомления имеет достаточный нижний отступ.
- Уведомление помечается прочитанным только после фактического просмотра нижней части.

## 4. Архитектурные блоки

### 4.1. Домен операций

Ввести нормализованную модель:

```ts
type OperationStatus = "completed" | "processing" | "rejected" | "scheduled";
type OperationKind = "transfer" | "payment" | "topup" | "cashback" | "fee";

interface BankOperation {
  id: string;
  slug: string;
  kind: OperationKind;
  status: OperationStatus;
  amountMinor: number;
  currency: CurrencyCode;
  accountId: string;
  counterparty: string;
  category: string;
  occurredAt: string;
  feeMinor: number;
  rejectionReason?: string;
  legalDocumentIds: string[];
}
```

Требования:

- суммы хранятся в minor units;
- форматирование выполняется централизованно;
- настройка «расходы без минуса» меняет только представление;
- processing — нейтральный серый стиль;
- rejected — красный стиль и обязательная причина;
- completed — акцентный/успешный стиль;
- scheduled — отдельный статус и дата исполнения.

### 4.2. Генератор аналитики

Создать чистый вычислительный модуль без React-зависимостей. Вход: счета, карты, операции, период, валюта отображения. Выход:

- доходы, расходы, чистый денежный поток;
- средний дневной расход;
- медианный платёж;
- прогноз остатка на 7/30 дней;
- категории и доли расходов;
- recurring-платежи;
- аномальные операции по отклонению от медианы;
- комиссия за период;
- динамика к предыдущему сопоставимому периоду;
- баланс по счетам и валютам;
- индекс финансовой устойчивости как демонстрационный показатель с объяснением формулы.

Вычисления мемоизируются по стабильному hash входных данных. UI-анимация «расчёт аналитики» проигрывается не чаще раза в час; timestamp сохраняется отдельно от результата.

### 4.3. Глобальные настройки

Расширить версионированную схему:

- валюта отображения;
- показывать/скрывать минус у расходов;
- icon pack: Lucide и второй npm-пак;
- динамический фон: off/cursor/navigation/operation/all;
- интенсивность glass/background blur;
- скорость и easing анимаций;
- период повторного запроса PIN;
- статус developer mode;
- пользовательские перестановки секций;
- формат единиц и региона;
- скрытие баланса;
- настройки отдельных карт.

Каждая категория имеет `resetCategory(categoryId)`, вся схема — `resetAll()`. Сброс PIN и кодовой фразы требует отдельного подтверждения.

### 4.4. PIN и кодовая фраза

Маршруты:

- `/settings/security/pin`
- `/settings/security/pin/create`
- `/settings/security/pin/change`
- `/settings/security/code-word`
- `/security/unlock`

Поведение:

- PIN никогда не хранится открытым текстом;
- для демонстрации использовать браузерный Web Crypto hash с солью;
- touch-устройства используют виртуальную цифровую клавиатуру без вызова нативной клавиатуры;
- физическая клавиатура поддерживает цифры, Enter, Backspace, Escape;
- количество попыток, задержка и сообщение об ошибке реализуются локально;
- интервал повторного запроса настраивается;
- после успешного ввода сохраняется timestamp сессии;
- Number Flow используется только для незащищённых индикаторов, цифры PIN визуально не раскрываются.

## 5. Навигация и header

### 5.1. Широкая версия

- Левая группа: поиск и контекст страницы.
- Дополнительные компактные индикаторы заполняют доступное место, но имеют приоритеты скрытия.
- Правая группа всегда прижата к правому краю: QR, уведомления, аватар/меню.
- Использовать `min-width: 0`, container queries или медиаправила по фактическому доступному пространству.

### 5.2. Узкая версия

Порядок с учётом приоритета:

1. аватар;
2. поиск как поле или иконка;
3. QR-оплата при достаточном месте;
4. уведомления.

После прокрутки ниже вычисленной высоты header + зазор появляется компактная sticky-строка поиска. Появление — opacity/blur/translateY не более 8 px, ease-out. Header не должен перерисовываться на каждый scroll tick; применять passive listener и requestAnimationFrame либо CSS-позиционирование с IntersectionObserver.

### 5.3. Нижняя навигация

- Пять основных категорий.
- Активная категория: зелёный текст, обводка и заполненный вариант иконки; без крупной заливки.
- Анимируемый индикатор не меняет геометрию соседей.
- Надписи не обрезаются многоточием без необходимости; для самой узкой ширины допускается уменьшение типографики.
- Dock округлый, glass, с безопасным отступом от края и нижней системной панели.

## 6. Поиск

- `Ctrl+K`/`Cmd+K` перехватывается на `window` в capture-фазе, вызывает `preventDefault()` и открывает поиск.
- Не перехватывать сочетание, если активен системный/браузерный контекст вне документа приложения невозможно; внутри документа дефолт блокируется всегда.
- Поиск открывается как полноэкранный overlay, закрывающий фон приложения.
- Вход/выход синхронно анимирует backdrop blur и содержимое.
- Содержит последние запросы, быстрые действия, квадратные карточки предложений и результаты по операциям/сервисам/настройкам.
- Результаты фильтруются с `useDeferredValue`.
- Навигация клавишами ArrowUp/ArrowDown/Enter/Escape и корректные aria-роли обязательны.

## 7. Операции

- Переименовать пользовательский раздел «История» в «Операции» во всех локалях и навигации.
- Реализовать сортировку, фильтры и пагинацию.
- Календарь поддерживает 1893–2108 годы.
- Первый выбор задаёт начало периода; второй — конец; повторный выбор того же дня создаёт single-day filter.
- Фильтр синхронизируется с URL search params без полной перезагрузки.
- Экран операции содержит статус, реквизиты, комиссию, юридические основания, timeline, похожие операции, действия скачать чек/поделиться/повторить/оспорить.
- Кнопка скачивания чека показывает прогресс.
- Share использует Web Share API при доступности и кастомный fallback-dialog.

## 8. Аналитика

- Главный экран аналитики строится из результата вычислительного модуля.
- Инфографика не должна загружать тяжёлую chart-библиотеку до открытия экрана.
- На мобильном главным остаётся баланс/карты, графики ниже.
- Добавить breakdown по категориям, cash-flow, recurring, прогноз, комиссии, сравнение периодов и объяснимые insights.
- Skeleton отображает форму будущего контента без скачка layout.

## 9. Платежи

- QR-оплата — видимое быстрое действие.
- Таблица/список операций имеет пагинацию и сортировку.
- Формы пополнения/перевода/оплаты не имеют фиксированной ширины.
- Сумма крупная, но динамически уменьшается без изменения высоты поля.
- Комиссия, лимит, курс и время исполнения видимы до подтверждения.
- На touch/узкой версии финальное подтверждение поддерживает slide-to-confirm.
- Модалка проверки операции доступна по высоте и не перекрывается dock.

## 10. Профиль и уровень счёта

Добавить быстрые действия:

- данные пользователя;
- уровень счёта;
- QR для пополнения/сборов/чаевых/донатов;
- документы: паспорт и ИНН;
- биометрия с подписью «Использовать» и Switch;
- код-пароль;
- кодовая фраза;
- выход красным действием.

На мобильном аватар и инициалы центрируются. Под ними показывается предложение повысить уровень счёта. Экран повышения счёта отделён от банковской подписки и объясняет именно лимиты/обслуживание аккаунта.

## 11. Настройки и developer mode

- Основные категории — адаптивная квадратная сетка.
- Developer mode не виден по умолчанию.
- В «О приложении» многократный тап/клик по номеру сборки открывает developer mode; показать feedback оставшихся тапов.
- Developer-раздел отделён сепаратором.
- В нём доступны валюта, формат расходов, icon pack, фон, перестановка секций, дата/время, сброс категорий, полный сброс, PIN/code-word reset.
- После каждой категории показывать небольшое релевантное предложение банка, не влияющее на бренд.

## 12. Правовая информация

Сетка документов включает минимум шесть карточек:

1. правила дистанционного банковского обслуживания;
2. политика обработки персональных данных;
3. cookie-политика;
4. тарифы и комиссии;
5. порядок обращений и оспаривания операций;
6. лицензии сторонних компонентов.

Каждый документ получает отдельный маршрут, содержание, дату редакции, оглавление и дисклеймер демо-приложения. Лицензии компилируются на этапе сборки в JSON и подгружаются лениво.

## 13. Лендинг и предложения

- Добавить больше предложений по накоплениям, бонусам, семье, подписке, картам и поддержке.
- Полноценный footer: продукты, сервисы, помощь, документы, разработка, контакты, языки.
- Неработающие placeholder-ссылки явно оформляются без фиктивного перехода.
- План подписки и уровень счёта не смешиваются.

## 14. Фон и theme ripple

- Настройка выключения цветного градиента не скрывает сетку.
- Динамический фон реагирует на курсор только через CSS custom properties, обновляемые в requestAnimationFrame.
- При переходе/открытии операции возможен краткий слабый импульс, не блокирующий UI.
- Theme ripple строится из фиксированного круга с transform:scale и цветом новой темы.
- Новая тема применяется в момент, когда круг закрыл viewport; затем overlay плавно исчезает.
- Исключить forced layout в цикле анимации и очистить overlay при отмене/быстрых повторных кликах.

## 15. Производительность

- Разделить тяжёлые client-компоненты по маршрутам и загружать динамически.
- Не импортировать chart/icon pack целиком.
- Дедуплицировать глобальные listeners.
- Scroll listeners passive; частые координаты хранить в refs/CSS variables.
- Длинные списки используют `content-visibility:auto` и пагинацию.
- Настройки читаются один раз через provider с версионированной миграцией.
- Избегать повторного JSON parse cookies/local storage в каждом компоненте.
- Проверить hydration, layout shifts и bundle composition.

## 16. Expo — решение по границам релиза

Expo-приложение не создаётся в этом web-релизе автоматически. Подготовить отдельный документ реализуемости:

- какие доменные модули можно переиспользовать;
- какие UI-компоненты требуют React Native реализации;
- хранение секретов, biometrics и secure storage;
- стратегия monorepo;
- стоимость поддержки web/Expo.

Начало Expo-разработки требует отдельного подтверждения, потому что меняет архитектуру и объём поставки.

## 19. Definition of Done

Релиз завершён только когда:

- все критичные дефекты со скриншотов устранены;
- новые функции доступны с клавиатуры и touch;
- проверки и production build проходят;
- мобильные страницы не имеют горизонтального overflow;
- PR содержит описание, список проверок и снимки/результаты;
- Vercel deployment доступен по рабочему URL;
- ограничения демонстрационного приложения и Expo-границы задокументированы.
